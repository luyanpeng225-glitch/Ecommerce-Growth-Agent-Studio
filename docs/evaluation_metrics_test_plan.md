# 效果指标与测试数据方案

项目名称：E-commerce Growth Agent Studio / 电商增长 Agent 工作台

这个文件用于补齐作品集里的“效果指标”部分。当前项目没有真实客户数据，所以这里采用 mock 测试数据和可复现的测试方法，避免夸大业务结果。

## 1. 测试目标

验证这个多 Agent 工作流是否能帮助企业电商运营团队完成以下事情：

- 从标准商品 Brief 进入完整 Agent Workflow。
- 每个 Agent / Skill 都能产出结构化结果。
- 高风险营销表达能被继承、标记和阻断。
- 最终报告能解释每一步的输入、输出、风险和下游交接。
- 运营人员可以更快获得活动规划、内容结构、视觉素材结构和复盘指标。

注意：这里评估的是“结构化规划效率”和“风险可控性”，不是承诺真实 GMV、CTR 或转化提升。

## 2. 指标定义

| 指标 | 定义 | 计算方式 | 当前 MVP 状态 |
| --- | --- | --- | --- |
| 任务完成率 | 每个测试商品是否跑完指定节点 | 成功产出节点数 / 应产出节点数 | 运动相机已完成 11/11 |
| 平均耗时 | 从 Brief 到最终结构化报告的耗时 | 人工基准估算 vs Agent 工作流记录 | 需要后续手动记录 |
| 人工修改率 | 人审后需要修改的字段比例 | 需修改字段数 / 抽检字段数 | 需要后续人工标注 |
| 幻觉率 | 没有 Brief 或上游证据支持的声明比例 | 无证据声明数 / 总声明数 | 当前通过 blocked gate 控制，待量化 |
| 合规阻断率 | 被 Brand Compliance Agent 阻断的高风险项比例 | blocked 项数 / 审核项数 | 已有阻断结论，待统计数量 |
| 结构化输出率 | 节点是否同时产出 JSON 和 Markdown | 有效结构化文件数 / 预期文件数 | 当前 9 个节点均有结构化产物 |
| 可追踪率 | 最终报告是否能追溯到上游节点 | 有来源字段数 / 抽检字段数 | 当前通过 Artifact Index 和 Workflow Trace 覆盖 |

## 5. 幻觉率检查方法

每个节点抽检 10 个关键声明，标注来源：

| 来源类型 | 含义 | 是否可用 |
| --- | --- | --- |
| brief_supported | 来自商品 Brief 或 schema 字段 | 可用 |
| upstream_supported | 来自上游 Agent / Skill 输出 | 可用 |
| inferred_with_risk | 合理推断，但需要人工确认 | 条件可用 |
| unsupported_claim | 没有证据支撑 | 不可用 |
| blocked_claim | 高风险或需证明材料 | 不可用于最终生成 |

幻觉率计算：

```text
幻觉率 = unsupported_claim 数量 / 抽检声明总数
```

## 6. 人工修改率检查方法

建议让人工评审每个节点抽检 20 个字段，标注：

- pass：无需修改。
- minor_edit：轻微改写。
- major_edit：需要重写。
- blocked：不能进入下游。

人工修改率计算：

```text
人工修改率 = (minor_edit + major_edit + blocked) / 抽检字段总数
```
